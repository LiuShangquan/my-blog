# 一，基础命令

## 一、Shell 基础概念

### 核心逻辑

- 系统内核是硬件资源管理者，用户无法直接操作，需通过 Shell（终端程序）作为 “翻译官” 沟通。
- 主流 Linux 系统（如红帽）默认使用 Bash 解释器，它是 Shell 的一种。

### Bash 解释器优势

1. Tab 键可补全命令、参数或文件内容。
2. 上下方向键调取历史执行命令。
3. 支持环境变量功能。
4. 可编写强大的批处理脚本。

## 二、命令执行必备知识

### 命令基本格式

- 结构：命令名称 [命令参数] 命令对象（用 1 个或多个空格间隔）。
- 参数格式：短格式（如`man -h`）和长格式（如`man --help`）。

### 帮助命令（man）

- 作用：查询其他命令的功能和参数用法，需切换 root 管理员身份执行。
- 常用按键操作：
  1. 翻页：空格键 / Page Down（下翻）、Page Up（上翻）。
  2. 跳转：home（首页）、end（尾页）。
  3. 搜索：/（从上至下）、?（从下至上），n/N 切换下一个 / 上一个结果。
  4. 退出：q 键。
- 帮助信息结构：包含 NAME（命令名）、SYNOPSIS（参数用法）、DESCRIPTION（说明）等 11 类内容。

### 实用快捷键

1. Ctrl+C：终止当前进程。
2. Ctrl+D：表示键盘输入结束。
3. Ctrl+l：清空终端内容（清屏）。
4. Tab：补全命令、参数或文件。

# 二，管道符、重定向与环境变量

## 一、输入输出重定向

重定向用于改变命令的输入 / 输出来源或目标，解决信息保存与定向处理问题。

### 1. 核心概念

- 标准输出（STDOUT）：文件描述符 1，默认输出到屏幕。
- 标准输入（STDIN）：文件描述符 0，默认从键盘输入。
- 错误输出（STDERR）：文件描述符 2，默认输出到屏幕。

### 2. 常用重定向符号

#### 输入重定向

- `命令 < 文件`：将文件作为命令的标准输入。
- `命令 << 分界符`：从标准输入读入，遇分界符停止。
- `命令 < 文件1 > 文件2`：以文件 1 为输入，文件 2 为标准输出。

#### 输出重定向

- `命令 > 文件`：标准输出重定向到文件（清空原有内容）。
- `命令 2> 文件`：错误输出重定向到文件（清空原有内容）。
- `命令 >> 文件`：标准输出追加到文件末尾。
- `命令 2>> 文件`：错误输出追加到文件末尾。
- `命令 >> 文件 2>&1` 或 `命令 &>> 文件`：标准输出与错误输出共同追加到文件。

------

## 二、管道符命令

### 1. 基本用法

- 输入方式：Shift + 反斜杠（\），执行格式为 `命令A | 命令B`。
- 核心作用：将前一个命令的输出作为后一个命令的标准输入，实现命令联动处理。
- 扩展使用：支持多命令串联，如 `命令A | 命令B | 命令C`，类似流水线作业。

### 2. 示例

- 组合 `grep /sbin/nologin /etc/passwd`（查找限制登录用户）和 `wc -l`（统计行数），可写成 `grep /sbin/nologin /etc/passwd | wc -l`。

## 四、常用的转义字符

用于处理命令中的特殊字符或变量，确保命令准确执行。

- 反斜杠（\）：使后续一个变量变为单纯字符。
- 单引号（' '）：转义其中所有变量，视为纯字符串。
- 双引号（" "）：保留变量属性，不转义（参数含空格时建议使用，避免歧义）。
- 反引号（··）：执行其中的命令并返回结果。

------

## 五、重要的环境变量

环境变量定义系统运行参数，Linux 中变量名通常大写，命令小写。

### 1. 命令执行流程

1. 判断命令是否为绝对 / 相对路径，是则直接执行。
2. 检查是否为别名命令。
3. 区分内部命令（直接执行）与外部命令（进入下一步）。
4. 通过 PATH 变量指定的路径查找外部命令并执行。

### 2. 核心环境变量（10 个）

| 变量名称     | 作用                        |
| ------------ | --------------------------- |
| HOME         | 用户主目录（家目录）        |
| SHELL        | 当前使用的 Shell 解释器名称 |
| HISTSIZE     | 输出的历史命令记录条数      |
| HISTFILESIZE | 保存的历史命令记录条数      |
| MAIL         | 邮件保存路径                |
| LANG         | 系统语言、语系名称          |
| RANDOM       | 生成随机数字                |
| PS1          | Bash 解释器的提示符         |
| PATH         | 定义解释器搜索命令的路径    |
| EDITOR       | 默认文本编辑器              |

### 3. 关键知识点

- 不建议将当前目录（.）添加到 PATH：避免执行公共目录中的恶意同名命令。
- 变量转换：`export 变量名` 可将一般变量转为全局变量（如 `export LINUX`）。

# 三，Vim 编辑器与 Shell 命令脚本

## 一、Vim 文本编辑器

### （一）核心基础

- 定位：Vi 编辑器的增强版（1991 年发布），默认安装于所有 Linux 系统，支持代码着色、错误修正
- 核心用途：修改系统配置文件、编写文档 / 脚本
- 三种模式：命令模式、输入模式、末行模式（模式切换是核心操作）

### （二）模式切换规则

1. 初始进入：默认命令模式
2. 命令模式 → 输入模式：按 `a`（光标后插入）、`i`（光标前插入）、`o`（新行插入）等键
3. 输入模式 → 命令模式：按 `Esc` 键
4. 命令模式 → 末行模式：按 `:`（冒号）键
5. 末行模式 → 命令模式：按 `Esc` 键

### （三）核心命令汇总

#### 1. 命令模式（光标控制、文本操作）

| 命令 | 作用                            |
| ---- | ------------------------------- |
| dd   | 删除（剪切）光标所在整行        |
| 5dd  | 剪切从光标开始的 5 行           |
| yy   | 复制光标所在整行                |
| 5yy  | 复制从光标开始的 5 行           |
| n    | 定位搜索结果的下一个匹配项      |
| N    | 定位搜索结果的上一个匹配项      |
| u    | 撤销上一步操作                  |
| p    | 将剪切 / 复制的内容粘贴到光标后 |

#### 2. 末行模式（保存退出、环境设置、搜索替换）

| 命令          | 作用                                  |
| ------------- | ------------------------------------- |
| :w            | 保存文件                              |
| :q            | 退出编辑器（未修改时）                |
| :q!           | 强制退出（放弃修改）                  |
| :wq!          | 强制保存并退出                        |
| :set nu       | 显示行号                              |
| :set nonu     | 隐藏行号                              |
| : 整数        | 跳转到指定行（如 :10 跳转到第 10 行） |
| :s/old/new    | 替换当前行第一个 old 为 new           |
| :s/old/new/g  | 替换当前行所有 old 为 new             |
| :%s/old/new/g | 替换全文所有 old 为 new               |
| / 字符串      | 从上至下搜索字符串                    |
| ? 字符串      | 从下至上搜索字符串                    |
| : 命令        | 执行系统命令（如 :ls 查看目录）       |

### （四）实战应用：修改系统关键配置

#### 1. 配置主机名称

1. 编辑配置文件：`vim /etc/hostname`
2. 删除原始内容，输入新主机名（如 [linuxprobe.com](https://linuxprobe.com/)）
3. 保存退出：`:wq!`
4. 验证：`hostname` 命令查看修改结果

#### 2. 配置网卡信息（静态 IP）

1. 进入网卡配置目录：`cd /etc/sysconfig/network-scripts`

2. 编辑网卡文件（网卡名通过 `ifconfig` 确认，如 ifcfg-ens160）：`vim ifcfg-ens160`

3. 写入配置参数：

   ```plaintext
   TYPE=Ethernet
   BOOTPROTO=static
   NAME=ens160
   ONBOOT=yes
   IPADDR=192.168.10.10
   NETMASK=255.255.255.0
   GATEWAY=192.168.10.1
   DNS1=192.168.10.1
   ```

4. 保存退出并重启网络服务（使配置生效）

#### 3. 配置软件仓库（YUM/DNF）

1. 进入仓库配置目录：`cd /etc/yum.repos.d/`

2. 创建 repo 文件：`vim rhel10.repo`（后缀必须为 .repo）

3. 写入配置参数：

   ```plaintext
   [仓库标识]
   name=描述信息
   baseurl=软件包来源（FTP/HTTP/本地文件）
   enabled=1（1启用，0禁用）
   gpgcheck=0（1校验，0不校验）
   # gpgkey=公钥文件路径（校验开启时需配置）
   ```

4. 挂载光盘并写入 `/etc/fstab`（永久挂载）

5. 验证：`dnf install httpd -y`（测试仓库可用性）

## 二、Shell 脚本编写

### （一）Shell 脚本基础

- 本质：Shell 解释器（如 bash）执行的命令集合，支持变量、参数、控制结构
- 工作方式：

  2. 批处理：预先编写脚本，一次性执行所有命令

### （二）脚本结构（完整脚本三要素）

```bash
#!/bin/bash  # 脚本声明：指定解释器（必须位于第一行）

pwd  # 可执行语句：Linux命令或逻辑代码
```

## 三、流程控制语句（脚本逻辑核心）

### （一）if 条件测试语句（按条件执行命令）

#### 1. 单分支结构（满足条件才执行）

```bash
if [ 条件 ]; then
  命令序列
fi
```

示例：如果目录不存在则创建 `if [ ! -d /test ]; then mkdir /test; fi`

#### 2. 双分支结构（二选一执行）

```bash
if [ 条件 ]; then
  命令序列1（条件成立）
else
  命令序列2（条件失败）
fi
```

示例：ping 通则提示正常，否则报警 `if ping -c1 192.168.10.1; then echo "正常"; else echo "报警"; fi`

#### 3. 多分支结构（多条件匹配）

```bash
if [ 条件1 ]; then
  命令序列1
elif [ 条件2 ]; then
  命令序列2
else
  命令序列3（所有条件均不满足）
fi
```

示例：根据分数评级（优秀 / 合格 / 不合格）

### （二）for 循环语句（遍历取值列表）

- 适用场景：处理有明确范围或列表的数据
- 结构：

```bash
for 变量名 in 取值列表; do
  命令序列
done
```

示例：批量创建用户 `for user in zhangsan lisi; do useradd $user; echo "123456" | passwd --stdin $user; done`

### （三）while 循环语句（按条件重复执行）

- 适用场景：循环次数不确定，满足条件则持续执行
- 结构：

```bash
while [ 条件 ]; do
  命令序列
done
```

示例：猜价格游戏 `while [ $guess -ne $price ]; do 提示输入并判断; done`

- 注意：若条件为 `true`，则会无限循环（需用 exit 退出）

### （四）case 条件测试语句（多模式匹配）

- 适用场景：根据变量的不同取值执行不同命令（类似 switch）
- 结构：

```bash
case 变量值 in
模式1)
  命令序列1
  ;;  # 结束当前分支
模式2)
  命令序列2
  ;;
*)  # 默认分支（所有模式不匹配时）
  命令序列3
esac
```

示例：判断输入字符类型 `case $input in [a-z]|[A-Z]) echo "字母"; ;; [0-9]) echo "数字"; ;; *) echo "特殊字符"; esac`

## 四、计划任务服务程序（自动化任务调度）

### （一）一次性计划任务（at 命令）

- 用途：执行一次临时任务
- 核心命令：
  1. 创建任务：`at 时间`（如 `at 23:30`，输入命令后按 Ctrl+D 确认）
  2. 查看任务：`at -l`（列出未执行的任务）
  3. 删除任务：`atrm 任务序号`（通过 at -l 查看序号）
- 示例：今晚 23:30 重启 httpd 服务 `at 23:30` → 输入 `systemctl restart httpd` → Ctrl+D

### （二）长期性计划任务（crond 服务）

- 用途：周期性重复执行任务（如每天、每周）

- 核心命令（crontab）：

  | 参数 | 作用                         |
  | ---- | ---------------------------- |
  | -e   | 编辑计划任务                 |
  | -u   | 指定执行用户（默认当前用户） |
  | -l   | 列出任务列表                 |
  | -r   | 删除计划任务                 |

#### 1. 任务参数格式

```plaintext
分钟 小时 日期 月份 星期 命令  # 字段用空格分隔
```

| 字段 | 取值范围 | 说明                               |
| ---- | -------- | ---------------------------------- |
| 分钟 | 0~59     | 必须填写，不能为空                 |
| 小时 | 0~23     | -                                  |
| 日期 | 1~31     | 与 “星期” 不能同时使用（避免冲突） |
| 月份 | 1~12     | -                                  |
| 星期 | 0~7      | 0 和 7 均代表星期日                |

#### 2. 示例

- 每周一凌晨 3:25 备份目录：`25 3 * * 1 tar -zcf /backup.tar.gz /home/wwwroot`
- 每天 12:00 清理临时文件：`0 12 * * * rm -rf /tmp/*`

#### 3. 注意事项

1. 注释：用 # 开头添加注释（说明任务功能、作者）
2. 字段约束：“分钟” 字段必须有值，“日期” 和 “星期” 不能同时设置
3. 命令路径：使用绝对路径（如 /usr/bin/tar 而非 tar），避免环境变量问题

## 二、文件权限与归属

### （一）文件权限定义

文件权限分为读（r）、写（w）、执行（x），分别对应不同操作能力：

| 权限        | 文件操作                   | 目录操作                             |
| ----------- | -------------------------- | ------------------------------------ |
| 可读（r）   | cat（读取文件内容）        | ls（查看目录列表）                   |
| 可写（w）   | vim（修改文件内容）        | touch（新建文件）、删除 / 重命名文件 |
| 可执行（x） | ./ 脚本（运行程序 / 脚本） | cd（进入目录）                       |

### （二）权限的字符与数字表示

#### 1. 权限分配对应关系

| 权限项   | 所有者 | 所属组 | 其他用户 |
| -------- | ------ | ------ | -------- |
| 字符表示 | r w x  | r w x  | r w x    |
| 数字表示 | 4 2 1  | 4 2 1  | 4 2 1    |

#### 2. 转换规则

- 字符转数字：累加对应权限值（如 rwx=4+2+1=7，rw-=4+2=6，r--=4）
- 数字转字符：根据数值拆分权限（如 755=rwxr-xr-x，744=rwxr--r--）

### （三）文件类型分类

| 类型标识 | 文件类型     | 说明                              |
| -------- | ------------ | --------------------------------- |
| -        | 普通文件     | 文本、配置、日志、脚本等          |

| l        | 链接文件     | 快捷方式                          |
| b        | 块设备文件   | 硬盘、光驱等硬件（/dev 目录常见） |
| c        | 字符设备文件 | 鼠标、键盘等硬件（/dev 目录常见） |
| p        | 管道文件     | 进程间通信使用                    |

## 三、文件的特殊权限

### （一）特殊权限作用

| 权限 | 应用场景   | 效果                                                   |
| ---- | ---------- | ------------------------------------------------------ |
| SUID | 二进制程序 | 执行者临时拥有程序所有者的权限（仅对可执行二进制有效） |
| SGID | 二进制程序 | 执行者临时拥有程序所属组的权限                         |
| SGID | 目录       | 目录内新创建文件自动继承该目录的用户组                 |
| SBIT | 目录       | 用户仅能删除自己的文件，无法删除他人文件               |

### （二）特殊权限设置参数

| 参数 | 作用           |
| ---- | -------------- |

| o+t  | 设置 SBIT 权限 |
| o-t  | 取消 SBIT 权限 |

### （三）权限转换示例

- 字符转数字：rwsrwSr-- → SUID (4)+SGID (2) + 所有者 rwx (7) + 所属组 rw-(6) + 其他 r--(4) → 6764

## 六、su 命令与 sudo 服务

### （一）核心原则

最小权限授权：仅赋予普通用户完成工作必需的额外权限。

### （二）sudo 命令

#### 1. 作用

允许普通用户执行原本仅 root 可操作的命令，支持限制命令范围、记录操作日志、密码有效期设置。

#### 2. 关键参数

| 参数 | 作用                             |
| ---- | -------------------------------- |
| -h   | 查看帮助                         |
| -l   | 列出当前用户可执行的 sudo 命令   |

| -k   | 清空密码有效期（下次需重新验证） |
| -b   | 后台执行命令                     |
| -p   | 自定义密码提示语                 |

#### 3. 配置文件

`/etc/sudoers`：集中管理用户权限，配置格式为：

```
谁可以使用 允许使用的主机 = （以谁的身份） 可执行命令的列表
```

### （三）su 命令

用于切换用户身份，sudo 更安全（可限制命令范围），su 直接切换全权限。

# 五，Linux 存储结构与硬盘管理

## 一、文件存储结构（一切从 “/” 开始）

### 1. 核心差异（Linux vs Windows）

- Windows：基于盘符（C/D/E 盘）的分区存储
- Linux：无盘符，所有文件从**根目录（/）** 出发，遵循 FHS 标准的倒树状结构

### 2. 关键规则

- 严格区分大小写（root、Root、rOOt 为不同目录）
- 文件名禁止包含斜杠（/）
- 目录功能标准化，按 FHS 定义存放对应文件

### 3. 常见目录及用途

| 目录名称    | 核心内容                                           |
| ----------- | -------------------------------------------------- |
| /boot       | 开机必需文件（内核、开机菜单、配置文件）           |
| /dev        | 所有设备与接口的文件形式（如硬盘、鼠标）           |
| /etc        | 系统及应用的配置文件（全局配置）                   |
| /home       | 普通用户主目录（每个用户独立文件夹）               |
| /root       | 管理员（root）的家目录                             |
| /bin        | 单用户模式下仍可使用的基础命令                     |
| /sbin       | 开机过程必需的系统命令                             |
| /media      | 临时挂载设备的目录（如 U 盘、光盘）                |
| /tmp        | 公共临时目录（所有用户可读写）                     |
| /var        | 动态变化文件（日志、缓存等）                       |
| /usr        | 系统软件安装目录（usr/local 存放用户自行安装软件） |
| /lost+found | 文件系统错误时的丢失文件片段存放目录               |

### 4. 路径表示

- 绝对路径：从根目录（/）开始（如`/home/user/file.txt`）
- 相对路径：相对于当前目录（如`../doc/file.txt`）

## 二、物理设备命名规则

### 1. 核心设备文件命名

| 硬件设备类型     | 文件名称格式  | 说明                                                   |
| ---------------- | ------------- | ------------------------------------------------------ |
| IDE 设备（少见） | /dev/hd[a-d]  | 早期硬盘接口，最多 4 个设备                            |
| SCSI/SATA/U 盘   | /dev/sd[a-z]  | 主流存储设备，a-z 代表 26 块硬盘（按内核识别顺序分配） |
| Virtio 设备      | /dev/vd[a-z]  | 虚拟化环境常用设备                                     |
| 光驱             | /dev/cdrom    | 光盘设备的默认链接                                     |
| 打印机           | /dev/lp[0-15] | 打印设备                                               |

### 2. 分区编号规则

- 主分区 / 扩展分区：编号 1-4（最多 4 个）
- 逻辑分区：编号从 5 开始（需基于扩展分区创建）
- 示例：`/dev/sda5`表示 “第一块 SCSI 硬盘的第 1 个逻辑分区”

### 3. 关键说明

- 设备名称由**udev 服务**按内核识别顺序分配，与主板插槽顺序无关
- 分区编号可手工指定，不一定连续

## 三、硬盘基础原理

### 1. 扇区与 MBR

- 硬盘由扇区组成，每个扇区默认 512 字节
- 第一个扇区包含：主引导记录（MBR，446 字节）+ 分区表（64 字节）+ 结束符（2 字节）
- 分区表最多记录 4 个主分区信息（每个分区占 16 字节）

### 2. 分区类型

- 主分区：直接使用，可安装系统，最多 4 个
- 扩展分区：非实际存储分区，仅作为逻辑分区的 “指针容器”，最多 1 个
- 逻辑分区：基于扩展分区创建，无数量限制（受硬盘容量影响）

## 四、文件系统

### 1. 主流文件系统对比

| 文件系统 | 特点                                                   | 适用场景                    |
| -------- | ------------------------------------------------------ | --------------------------- |
| Ext2     | 无日志功能，数据安全性低                               | SD 卡、U 盘（临时存储）     |
| Ext3     | 支持日志，异常宕机可修复                               | 早期 Linux 系统，小容量硬盘 |
| Ext4     | Ext3 改进版，支持 1EB 容量、无限子目录，批量分配 block | 主流 Linux 系统默认         |
| XFS      | 高性能日志文件系统，恢复快，支持 18EB 容量             | 大容量存储、高性能需求场景  |

### 2. 文件存储原理

- inode：存储文件属性（权限、所有者、大小、修改时间、数据地址），每个文件占 1 个 inode（默认 128 字节）
- block：存储文件实际内容，默认 4KB
  - 小文件（如 1KB）占用 1 个 block，浪费 3KB 空间
  - 大文件（如 5KB）占用 2 个 block（剩余 1KB 需单独占用）
- VFS（虚拟文件系统）：屏蔽不同文件系统差异，为用户提供统一访问接口

## 五、核心操作命令

### 1. 设备挂载与卸载

| 命令   | 功能               | 语法格式                         | 关键参数                                                 |
| ------ | ------------------ | -------------------------------- | -------------------------------------------------------- |
| mount  | 挂载设备           | `mount [参数] 设备文件 挂载目录` | -a：挂载 /etc/fstab 中所有文件系统；-t：指定文件系统类型 |

| df     | 查看已挂载设备空间 | `df -h`                          | -h：人类可读格式（KB/MB/GB）                             |

### 2. 硬盘分区与格式化

| 命令  | 功能             | 语法格式                     | 关键参数                                                     |
| ----- | ---------------- | ---------------------------- | ------------------------------------------------------------ |
| fdisk | 分区管理         | `fdisk 磁盘名称`             | -n：新建分区；-d：删除分区；-p：查看分区表；-w：保存退出；-q：不保存退出 |
| mkfs  | 格式化分区       | `mkfs.文件系统类型 分区文件` | 如`mkfs.ext4 /dev/sdb1`、`mkfs.xfs /dev/sdb2`                |

| 命令      | 功能                  | 语法格式                         | 关键参数                                   |
| --------- | --------------------- | -------------------------------- | ------------------------------------------ |
| xfs_quota | 管理 XFS 文件系统配额 | `xfs_quota [参数] 配额 文件系统` | -x：专家模式；-c：执行命令                 |
| edquota   | 编辑用户 / 组配额     | `edquota [参数] 用户名`          | -u：用户配额；-g：组配额；-t：设置宽限期限 |

### 4. 软硬链接（ln）

| 命令 | 功能     | 语法格式                      | 关键参数                                                   |
| ---- | -------- | ----------------------------- | ---------------------------------------------------------- |
| ln   | 创建链接 | `ln [参数] 原始文件 链接文件` | -s：创建软链接（默认硬链接）；-f：强制创建；-i：覆盖前询问 |

### 5. 软硬链接差异

| 特性         | 硬链接                         | 软链接（符号链接）           |
| ------------ | ------------------------------ | ---------------------------- |
| 原理         | 复制 inode，指向原始文件 block | 仅记录原始文件的路径和名称   |
| 原始文件删除 | 仍可访问（inode 未删除）       | 失效（链接指向不存在的路径） |
| 原始文件改名 | 可正常访问                     | 可正常访问（路径未变）       |
| 跨文件系统   | 不支持                         | 支持                         |
| 目录链接     | 不支持                         | 支持                         |



## 六、其他应用

### 1. 交换分区（SWAP）

- 作用：临时存储内存中不常用数据，释放物理内存给活跃程序
- 大小建议：物理内存的 1.5-2 倍
- 创建流程：分区（类型 82）→ 格式化（mkswap）→ 启用（swapon）→ 永久生效（写入 /etc/fstab）

### 2. 磁盘配额（quota）

- 核心功能：限制用户 / 组的最大硬盘空间或文件个数
- 限制类型：
  - 软限制：触发后提示，允许宽限期内继续使用
  - 硬限制：触发后强制终止操作，不允许超额
- 适用场景：多用户共享服务器，防止单个用户占满硬盘

#### 		创建流程

1. 启用配额支持：

   ```
   echo '/dev/sdb3 /data xfs defaults,usrquota,grpquota 0 0' >> /etc/fstab
   ```

2. 激活配额服务

   ```bash
   xfs_quota -x -c 'quotaon /data'
   ```

3. 设置配额xfs_quota

   ```
   xfs_quota -x -c 'limit bsoft=3m bhard=6m isoft=3 ihard=6 tom' /boot
   ```

4. 修改配额edquota

   ```
   edquota -u tom
   ```

### 3. VDO（虚拟数据优化）

- 原理：通过**数据删重**（重复文件仅存一份指针）和**自动压缩**优化逻辑存储空间
- 特点：
  - 不增加物理存储，仅提升逻辑可用空间
  - 兼容加密技术（需先加密再用 VDO）
  - 不可叠加使用（1TB 物理空间无法通过多次 VDO 扩展为 100TB）
- 效果：可执行程序、数据库文件压缩比最高，纯文本 / 图片压缩效果有限

# 六，RAID 与 LVM 磁盘阵列技术

## 一、课程核心目标

1. 掌握常用 RAID 技术方案（0、1、5、10）的特性，能部署 RAID 10、RAID 5 + 备份盘等方案，满足生产环境对 IO 读写速度和数据冗余的需求。
2. 理解 LVM（逻辑卷管理器）的核心原理，掌握其部署、扩容、缩容、快照及卸载删除的完整操作流程。

## 二、RAID（独立冗余磁盘阵列）

### （一）核心定义

将多块物理硬盘（至少 2 块）通过硬件或软件串联，组成卷组，集中管理数据存储，平衡读写速度与数据安全性。

### （二）常用 RAID 级别对比

| RAID 级别 | 最少硬盘 | 可用容量 | 读写性能 | 安全性 | 核心特点                                                     |
| --------- | -------- | -------- | -------- | ------ | ------------------------------------------------------------ |
| 0         | 2        | n        | n        | 低     | 追求最大容量和速度；单块硬盘损坏则数据全丢                   |
| 1         | 2        | n/2      | n        | 高     | 数据镜像备份；只要 1 块硬盘可用，数据不受影响                |
| 5         | 3        | n-1      | n-1      | 中     | 存储奇偶校验信息（分散在各硬盘）；允许 1 块硬盘异常          |
| 10        | 4        | n/2      | n/2      | 高     | RAID 1+RAID 0 组合；先两两组 RAID 1 保障安全，再组 RAID 0 提升速度；允许一半硬盘异常（不同 RAID 1 阵列中） |

### （三）关键技术原理

1. **RAID 0**：数据依次写入各物理硬盘，无冗余，仅追求速度和容量。
2. **RAID 1**：数据同步镜像到两块硬盘，牺牲容量换安全性。
3. **RAID 5**：奇偶校验信息分散存储在除自身外的所有硬盘，兼顾成本、容量、速度和安全性。
4. **RAID 10**：组合 RAID 1 的冗余和 RAID 0 的速度，需 4 块硬盘起步。

### （四）部署与管理工具：mdadm 命令

#### 1. 常用参数

| 参数 | 作用           |
| ---- | -------------- |
| -a   | 检测设备名称   |
| -n   | 指定设备数量   |
| -l   | 指定 RAID 级别 |
| -C   | 创建 RAID 阵列 |
| -v   | 显示操作过程   |
| -f   | 模拟设备损坏   |
| -r   | 移除故障设备   |
| -Q   | 查看摘要信息   |
| -D   | 查看详细信息   |
| -S   | 停止 RAID 阵列 |

#### 2. 核心操作流程

##### （1）部署 RAID 阵列

1. 添加所需数量的物理硬盘（如 RAID 10 需 4 块，RAID 5 + 备份盘需 4 块）。
2. 用`mdadm -C -v /dev/md0 -l [级别] -n [设备数] /dev/sd[b-e]`创建阵列（示例设备名）。
3. 格式化并挂载阵列，即可使用。`mkfs.ext4 /dev/md0 ` , `mount /dev/md0 /RAID`

##### （2）损坏与修复

1. 确认故障硬盘，用`mdadm -f /dev/md0 /dev/sdX`标记损坏，`mdadm -r /dev/md0 /dev/sdX`移除。
2. 新增硬盘，用`mdadm -a /dev/md0 /dev/sdY`添加到阵列，自动同步数据。
3. RAID 10 中单个 RAID 1 阵列故障不影响整体使用，期间可正常读写文件。

##### （3）RAID + 备份盘（热备盘）

1. 核心作用：预防同一 RAID 1 阵列中硬盘全损的极端情况，备份盘平时闲置，故障时自动顶替。

2. 部署要求：RAID 5 需 3 块数据盘 + 1 块备份盘，共 4 块硬盘。

   `mdadm -Cv /dev/md0 -n 3 -l 5 -x 1 /dev/sdb /dev/sdc /dev/sdd /dev/sde`

##### （4）删除 RAID 阵列

1. 停用阵列：`mdadm -S /dev/md0`。
2. 移除所有硬盘：`mdadm -r /dev/md0 /dev/sd[b-e]`。
3. 清理残留设备文件（老版本系统）：`mdadm --remove /dev/md0`。

## 三、LVM（逻辑卷管理器）

### （一）核心定义

Linux 系统的硬盘分区管理机制，在硬盘分区与文件系统间添加逻辑层，通过抽象卷组整合多块硬盘，实现分区动态扩容 / 缩容，避免传统分区调整的数据丢失风险。

### （二）核心概念（从底层到上层）

1. **物理卷（PV）**：最底层，可是物理硬盘、硬盘分区或 RAID 阵列。
2. **卷组（VG）**：建立在物理卷之上，可包含多个 PV，支持后续添加新 PV 扩容。
3. **逻辑卷（LV）**：基于卷组空闲资源创建，可动态扩展 / 缩小空间，直接用于格式化和挂载。

### （三）常用 LVM 命令

| 功能 | 物理卷管理 | 卷组管理  | 逻辑卷管理 |
| ---- | ---------- | --------- | ---------- |
| 扫描 | pvscan     | vgscan    | lvscan     |
| 建立 | pvcreate   | vgcreate  | lvcreate   |
| 显示 | pvdisplay  | vgdisplay | lvdisplay  |
| 删除 | pvremove   | vgremove  | lvremove   |
| 扩展 | -          | vgextend  | lvextend   |
| 缩小 | -          | vgreduce  | lvreduce   |

### （四）核心操作流程

#### 1. 部署 LVM

1. 添加物理硬盘，执行`pvcreate /dev/sd[bc]`（示例设备），使硬盘支持 LVM。
2. 创建卷组：`vgcreate storage /dev/sd[bc]`（卷组名 storage）。
3. 切割逻辑卷：`lvcreate -L 150M -n vo storage`（逻辑卷名 vo，大小 150MB）。
4. 格式化并挂载：`mkfs.ext4 /dev/storage/vo`，`mount /dev/storage/vo /mnt/lv`。

#### 2. 扩容逻辑卷（示例：扩展至 290MB）

1. 取消挂载：`umount /mnt/lv`。
2. 扩容逻辑卷：`lvextend -L 290M /dev/storage/vo`。
3. 同步文件系统：`e2fsck -f /dev/storage/vo`（检查完整性），`resize2fs /dev/storage/vo`（同步容量）。
4. 重新挂载：`mount /dev/storage/vo /mnt/lv`，验证容量。

#### 3. 缩容逻辑卷（示例：缩小至 120MB）

1. 取消挂载：`umount /mnt/lv`。
2. 检查文件系统完整性（关键，防数据丢失）：`e2fsck -f /dev/storage/vo`。
3. 同步文件系统容量：`resize2fs /dev/storage/vo 120M`。
4. 缩容逻辑卷：`lvreduce -L 120M /dev/storage/vo`。
5. 重新挂载：`mount /dev/storage/vo /mnt/lv`，验证容量。

#### 4. 逻辑卷快照（一次性有效）

1. 创建快照：`lvcreate -s -L [逻辑卷容量] -n vo_snap /dev/storage/vo`（快照容量需与原逻辑卷一致）。
2. 测试快照：在挂载目录创建文件，查看快照占用空间上升。
3. 快照还原：先卸载原逻辑卷`umount /mnt/lv`，执行`lvconvert --merge /dev/storage/vo_snap`，还原后快照自动删除，新增文件消失。

#### 5. 删除 LVM

1. 取消挂载：`umount /mnt/lv`，删除 /etc/fstab 中永久挂载配置。
2. 删除逻辑卷：`lvremove /dev/storage/vo`（需确认 y）。
3. 删除卷组：`vgremove storage`。
4. 删除物理卷：`pvremove /dev/sd[bc]`。

# Linux 防火墙管理工具

## 一、防火墙基础概念

### 核心作用

作为公网与内网的保护屏障，依据预设策略过滤穿越自身的网络流量。

### 本质区别

- 防火墙硬件 / 软件：物理设备或系统程序，核心是流量过滤
- 管理工具（iptables/firewalld）：并非真正防火墙，仅用于定义策略规则
- 内核处理框架：iptables 依赖 netfilter，firewalld 依赖 nftables

### 策略规则逻辑

1. 匹配顺序：从上到下读取，匹配成功即执行对应动作（放行 / 阻止）
2. 默认策略：无匹配规则时执行，需遵循 "堵则设通，通则设堵" 原则
3. 动作类型：放行（ACCEPT）、阻止（DROP/REJECT）

## 二、iptables 防火墙

### 核心特性

- 属于数据链路层服务，基于 OSI 七层模型实现流量匹配
- 支持按源 / 目标地址、协议、端口、网卡等多维度匹配

### 规则链分类（5 类核心链）

| 规则链      | 作用                 |
| ----------- | -------------------- |
| PREROUTING  | 路由选择前处理数据包 |
| INPUT       | 处理流入本机的数据包 |
| OUTPUT      | 处理流出本机的数据包 |
| FORWARD     | 处理转发的数据包     |
| POSTROUTING | 路由选择后处理数据包 |

### 常用命令参数

| 参数         | 作用                              |
| ------------ | --------------------------------- |
| -P           | 设置默认策略（如 DROP/ACCEPT）    |
| -F           | 清空所有规则链                    |
| -L           | 查看规则链配置                    |
| -A           | 在规则链末尾添加新规则            |
| -I num       | 在规则链指定位置（num）添加新规则 |
| -D num       | 删除规则链中第 num 条规则         |
| -s IP/MASK   | 匹配源地址（! 表示排除）          |
| -d IP/MASK   | 匹配目标地址                      |
| -i 网卡名    | 匹配流入网卡的流量                |
| -o 网卡名    | 匹配流出网卡的流量                |
| -p 协议      | 匹配协议（TCP/UDP/ICMP 等）       |
| --dport 端口 | 匹配目标端口                      |
| --sport 端口 | 匹配源端口                        |

### 经典实验操作

1. 查看规则：`iptables -L`
2. 清空规则：`iptables -F`
3. 设置 INPUT 默认拒绝：`iptables -P INPUT DROP`
4. 允许 ICMP 流量（ping）：`iptables -A INPUT -p icmp -j ACCEPT`
5. 拒绝指定 IP 访问 80 端口：`iptables -A INPUT -s 192.168.10.5 -p tcp --dport 80 -j REJECT`
6. 仅允许指定网段访问 22 端口：`iptables -A INPUT -s 192.168.10.0/24 -p tcp --dport 22 -j ACCEPT`
7. 拒绝 1000-1024 端口访问：`iptables -A INPUT -p tcp --dport 1000:1024 -j REJECT`

## 三、firewalld 防火墙

### 核心优势

- 动态防火墙管理器，支持策略实时更新（无需重启服务）
- 引入 "区域" 概念，实现策略快速切换
- 支持 CLI（命令行）和 GUI（图形界面）两种管理方式

### 区域分类及默认策略

| 区域          | 默认策略                                                     |
| ------------- | ------------------------------------------------------------ |
| trusted       | 允许所有数据包                                               |
| home/internal | 拒绝流入，允许与流出相关流量及 ssh、mdns 等服务流量          |
| work          | 拒绝流入，允许与流出相关流量及 ssh、ipp-client 等服务流量    |
| public        | 拒绝流入，允许与流出相关流量及 ssh、dhcpv6-client 服务流量   |
| external      | 拒绝流入，允许与流出相关流量及 ssh 服务流量                  |
| dmz           | 拒绝流入，允许与流出相关流量及 ssh 服务流量                  |
| block/drop    | 拒绝流入，仅允许与流出相关流量（drop 不回送拒绝信息，block 回送） |

### 常用命令参数（firewall-cmd）

| 参数                        | 作用                                    |
| --------------------------- | --------------------------------------- |
| --get-default-zone          | 查询默认区域                            |
| --set-default-zone=<区域>   | 设置默认区域（永久生效）                |
| --get-active-zones          | 查看当前活跃区域及绑定网卡              |
| --add-service=<服务名>      | 允许指定服务流量（默认区域）            |
| --add-port=<端口 / 协议>    | 允许指定端口流量（默认区域）            |
| --remove-service=<服务名>   | 禁止指定服务流量                        |
| --remove-port=<端口 / 协议> | 禁止指定端口流量                        |
| --reload                    | 使永久配置生效，覆盖当前配置            |
| --panic-on/--panic-off      | 开启 / 关闭应急模式（阻断所有网络连接） |
| --add-source=<IP / 子网>    | 将指定来源流量导向目标区域              |
| --list-all-zones            | 查看所有区域的完整配置                  |

### 经典实验操作

1. 查看当前区域：`firewall-cmd --get-active-zones`
2. 设置默认区域为 public：`firewall-cmd --set-default-zone=public`
3. 永久允许 HTTPS 流量并生效：`firewall-cmd --permanent --add-service=https && firewall-cmd --reload`
4. 临时允许 8080-8081 端口：`firewall-cmd --add-port=8080-8081/tcp`
5. 端口转发（888→22，永久 + 实时生效）：`firewall-cmd --permanent --add-forward-port=port=888:proto=tcp:to-port=22 && firewall-cmd --reload`
6. 开启应急模式：`firewall-cmd --panic-on`

### 图形管理工具（firewall-config）

#### 核心功能

1. 模式切换：运行时（Runtime）/ 永久（Permanent）
2. 区域管理：绑定网卡、设置默认区域
3. 服务 / 端口控制：勾选允许的服务，添加允许的端口范围
4. 高级配置：SNAT、端口转发、富规则（优先级最高）、ICMP 过滤

#### 操作流程

1. 挂载系统镜像并配置软件仓库（BaseOS 与 AppStream）
2. 选择配置模式（永久 / 运行时）
3. 配置服务 / 端口放行规则
4. 开启 SNAT 或端口转发
5. 点击 "Reload Firewalld" 使配置生效

# Linux ssh远程管理与网络服务配置

## 一、配置网络服务（Network Services Configuring）

> 注：服务器 IP 固定为`192.168.10.10`，客户端为`192.168.10.20/30`，便于统一配置。

### （二）网络会话管理（nmcli 命令）

- 底层依赖`NetworkManager`守护进程，支持创建 / 切换 / 删除网络会话，适配不同场景（如办公室 / 家庭网络）。

1. 核心操作代码示例：

   ```bash
   # 1. 查看当前网络会话
   [root@linuxprobe ~]# nmcli connection show
   # 2. 创建新会话（命名为"office"，IP自动获取）
   [root@linuxprobe ~]# nmcli connection add type ethernet con-name office ifname ens160
   # 3. 创建固定IP会话（命名为"home"，IP 192.168.2.10/24）
   [root@linuxprobe ~]# nmcli connection add type ethernet con-name home ifname ens160 ip4 192.168.2.10/24 gw4 192.168.2.1
   # 4. 切换会话（从office切换到home）
   [root@linuxprobe ~]# nmcli connection up home
   # 5. 删除无用会话
   [root@linuxprobe ~]# nmcli connection delete office
   ```

   

### （三）网卡绑定技术（round-robin 模式）

1. **作用**：提高网络传输速度，实现故障冗余（7×24 小时服务），两块网卡同时工作，一块故障时自动切换。

2. **前提**：虚拟机添加两块同模式网卡（如`仅主机模式`），识别为`ens160`和`ens192`。

3. 完整配置代码示例：

   ```bash
   # 1. 安装网卡绑定工具（若未安装）
   [root@linuxprobe ~]# dnf install -y teamd
   # 2. 创建bond0虚拟网卡（round-robin模式，命名为"bond0"）
   [root@linuxprobe ~]# nmcli connection add type team con-name bond0 ifname bond0 config '{"runner":{"name":"roundrobin"}}'
   # 3. 配置bond0的IP地址
   [root@linuxprobe ~]# nmcli connection modify bond0 ipv4.addresses 192.168.10.10/24 ipv4.gateway 192.168.10.1 ipv4.dns 192.168.10.1 ipv4.method manual
   # 4. 将两块物理网卡添加到bond0
   [root@linuxprobe ~]# nmcli connection add type team-slave con-name bond0-ens160 ifname ens160 master bond0
   [root@linuxprobe ~]# nmcli connection add type team-slave con-name bond0-ens192 ifname ens192 master bond0
   # 5. 启动bond0服务
   [root@linuxprobe ~]# nmcli connection up bond0
   # 6. 验证绑定状态
   [root@linuxprobe ~]# teamdctl bond0 state
   ```

   

## 三、远程控制服务（Remote Control Service）

### （一）SSH 与 sshd 基础

1. **SSH（Secure Shell）**：加密远程登录协议，替代明文传输的 Telnet，默认端口 22；

2. sshd 服务

   ：Linux 系统默认安装，需确保服务正常运行：

   ```bash
   # 查看sshd服务状态
   [root@linuxprobe ~]# systemctl status sshd
   # 启动并设置开机自启
   [root@linuxprobe ~]# systemctl enable --now sshd
   ```

3. **sshd 配置参数说明**：

| 参数                         | 作用               | 安全建议                           |
| ---------------------------- | ------------------ | ---------------------------------- |
| `Port 22`                    | 默认服务端口       | 改为 1024-65535 之间的非知名端口   |
| `PermitRootLogin yes`        | 允许 root 直接登录 | 设为`no`，通过普通用户 + sudo 管理 |
| `PasswordAuthentication yes` | 启用密码验证       | 设为`no`，仅用密钥验证             |
| `MaxAuthTries 6`             | 最大密码尝试次数   | 改为`3`，减少暴力破解机会          |

### （三）两种验证方式（代码示例）

#### 1. 密码验证（简单但安全性较低）

- 客户端连接命令

  （以 Xshell 或本地终端为例）：

  ```bash
  # 格式：ssh 用户名@远程IP -p 端口（默认22可省略）
  [user@client ~]$ ssh root@192.168.10.10
  # 输入密码后登录（密码输入时不显示）
  root@192.168.10.10's password: 
  [root@linuxprobe ~]#  # 登录成功
  ```

#### 2. 密钥验证（高安全性，免密码登录）

- 步骤 1：客户端生成密钥对

  （无密码则直接回车，有密码则设置密钥密码）：

  ```bash
  [user@client ~]$ ssh-keygen -t rsa  # rsa算法生成密钥对
  Generating public/private rsa key pair.
  Enter file in which to save the key (/home/user/.ssh/id_rsa):  # 按回车用默认路径
  Enter passphrase (empty for no passphrase):  # 可选：设置密钥密码（双重安全）
  Enter same passphrase again: 
  Your identification has been saved in /home/user/.ssh/id_rsa.  # 私钥（需保密）
  Your public key has been saved in /home/user/.ssh/id_rsa.pub.  # 公钥（可公开）
  ```

  

- 步骤 2：上传公钥到服务器

  （客户端执行）：

  ```bash
  # 格式：ssh-copy-id 用户名@远程IP -p 端口
  [user@client ~]$ ssh-copy-id root@192.168.10.10
  /usr/bin/ssh-copy-id: INFO: Source of key(s) to be installed: "/home/user/.ssh/id_rsa.pub"
  Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
  root@192.168.10.10's password:  # 首次需输入服务器密码
  Number of key(s) added: 1
  ```

- 步骤 3：服务器禁用密码验证；

```bash
    # 编辑配置文件
    [root@linuxprobe ~]# vim /etc/ssh/sshd_config
    # 1. 禁用root直接登录（提高安全性）
    PermitRootLogin no
    # 2. 禁用密码验证（仅允许密钥登录）
    PasswordAuthentication no
    # 3. 修改默认端口（可选，避免暴力破解）
    Port 2222
    # 4. 保存退出后重启sshd
    [root@linuxprobe ~]# systemctl restart sshd
```

- 步骤 4：客户端免密码登录

  ```bash
  [user@client ~]$ ssh root@192.168.10.10
  # 若设置了密钥密码，仅需输入一次密钥密码，后续免输
  Enter passphrase for key '/home/user/.ssh/id_rsa': 
  [root@linuxprobe ~]#  # 登录成功
  ```

### （四）远程传输命令（scp）

1. **功能**：基于 SSH 协议安全传输文件 / 文件夹，支持本地→远程、远程→本地。

2. 核心代码示例

   ```bash
   # 1. 本地文件→远程（将/root/out.txt传至192.168.10.20的/home目录）
   [root@linuxprobe ~]# scp /root/out.txt root@192.168.10.20:/home
   root@192.168.10.20's password:  # 验证密码（密钥登录免输）
   out.txt                                      100%  123   456.0KB/s   00:00 
   
   # 2. 本地文件夹→远程（加-r参数，传输/root/docs文件夹）
   [root@linuxprobe ~]# scp -r /root/docs root@192.168.10.20:/home
   
   # 3. 远程文件→本地（将192.168.10.10的/var/log/messages传至本地/root目录）
   [user@client ~]$ scp root@192.168.10.10:/var/log/messages /root
   
   # 4. 指定端口传输（若sshd端口改为2222）
   [root@linuxprobe ~]# scp -P 2222 /root/out.txt root@192.168.10.20:/home
   ```

   

3. **scp 参数说明**：

| 参数 | 作用                           |
| ---- | ------------------------------ |
| `-v` | 显示详细传输进度（排障用）     |
| `-P` | 指定远程 sshd 端口（注意大写） |
| `-r` | 递归传输文件夹                 |
| `-6` | 使用 IPv6 协议传输             |

## 四、不间断会话服务（Uninterrupted Session Service）

### （一）Tmux 服务基础

1. **作用**：网络中断不丢失会话、多窗格并行操作、多人会话共享，适合长时间远程任务（如编译、日志监控）。

2. 安装与启动

   ```bash
   # 安装Tmux（RHEL/CentOS）
   [root@linuxprobe ~]# dnf install -y tmux
   # 启动Tmux（默认创建一个会话）
   [root@linuxprobe ~]# tmux
   ```

   

### （二）Tmux 核心操作（代码 + 快捷键）

#### 1. 会话管理（创建 / 恢复 / 删除）

| 操作         | 命令                          | 说明                                                   |
| ------------ | ----------------------------- | ------------------------------------------------------ |
| 创建会话     | `tmux new -s 会话名`          | 示例：`tmux new -s compile`（创建名为 compile 的会话） |
| 查看会话列表 | `tmux ls`                     | 退出会话后查看所有后台会话                             |
| 恢复会话     | `tmux attach -t 会话名`       | 示例：`tmux attach -t compile`（恢复 compile 会话）    |
| 临时退出会话 | `Ctrl+b + d`                  | 会话后台运行，终端可执行其他命令                       |
| 强制关闭会话 | `tmux kill-session -t 会话名` | 示例：`tmux kill-session -t compile`                   |

#### 2. 多窗格管理（快捷键为主）

1. 窗格划分与切换

   ```bash
   # 1. 进入Tmux会话后，按Ctrl+b激活快捷键，再执行：
   Ctrl+b + "  # 上下划分窗格（示例：上方运行top，下方执行命令）
   Ctrl+b + %  # 左右划分窗格（示例：左侧vim编辑，右侧查看日志）
   Ctrl+b + 方向键  # 切换到上下左右窗格（如Ctrl+b + ↑切换到上方窗格）
   Ctrl+b + q  # 显示窗格编号（按编号快速切换，如按1切换到编号1的窗格）
   ```

   

2. 窗格操作进阶

   ```bash
   # 1. 关闭当前窗格（确保数据已保存）
   Ctrl+b + X  # 按y确认关闭
   
   # 2. 窗格位置互换
   Ctrl+b + {  # 当前窗格与左侧/上方窗格互换
   Ctrl+b + }  # 当前窗格与右侧/下方窗格互换
   
   # 3. 调整窗格大小（按住Ctrl+b，再按方向键拖动）
   Ctrl+b + 按住↑/↓/←/→  # 缩小/放大当前窗格
   ```

   

#### 3. 会话共享（多人协作）

- 步骤 1：服务器创建共享会话

  ：

  ```bash
  [root@linuxprobe ~]# tmux new -s share  # 创建名为share的会话
  ```

  

- 步骤 2：其他客户端登录服务器后，加入共享会话

  ：

  ```bash
  [user@client2 ~]$ ssh root@192.168.10.10  # 登录服务器
  [root@linuxprobe ~]# tmux attach -t share  # 加入share会话
  ```

  

- **效果**：所有用户操作实时同步，适合教学、协作排障。

## 五、检索日志信息（Retrieve Log Information）

### （一）常见日志文件路径与用途

| 文件路径            | 作用                                 | 查看命令示例                                   |
| ------------------- | ------------------------------------ | ---------------------------------------------- |
| `/var/log/boot.log` | 系统开机自检与引导信息               | `cat /var/log/boot.log`                        |
| `/var/log/lastlog`  | 用户登录成功记录（时间 / IP / 终端） | `lastlog`（专用命令）                          |
| `/var/log/btmp`     | 用户登录失败记录                     | `lastb`（专用命令）                            |
| `/var/log/messages` | 系统及服务运行 / 报错信息            | `tail -f /var/log/messages`（实时查看）        |
| `/var/log/secure`   | 安全日志（SSH 登录、sudo 操作）      | `grep "sshd" /var/log/secure`（筛选 SSH 日志） |
| `/var/log/wtmp`     | 系统启动 / 关机、用户登录时长        | `last`（专用命令）                             |

### （二）journalctl 命令（系统日志统一检索）

1. **核心优势**：无需记忆日志路径，支持按服务、时间、等级筛选，实时追踪。

2. 代码示例（常用场景）

   ```bash
   # 1. 查看sshd服务的所有日志
   [root@linuxprobe ~]# journalctl -u sshd
   
   # 2. 查看最近10条内核日志（排障硬件/驱动问题）
   [root@linuxprobe ~]# journalctl -k -n 10
   
   # 3. 查看今天的错误等级日志（仅显示err及以上级别）
   [root@linuxprobe ~]# journalctl -p err --since today
   
   # 4. 实时追踪nginx服务日志（类似tail -f）
   [root@linuxprobe ~]# journalctl -u nginx -f
   
   # 5. 查看某时间段的日志（2024-05-01 10:00到12:00）
   [root@linuxprobe ~]# journalctl --since "2024-05-01 10:00" --until "2024-05-01 12:00"
   
   # 6. 查看日志文件占用空间
   [root@linuxprobe ~]# journalctl --disk-usage
   ```

   

3. **journalctl 参数与日志等级说明**：

| 参数      | 作用              | 日志等级（从高到低） | 说明                         |
| --------- | ----------------- | -------------------- | ---------------------------- |
| `-u`      | 指定服务名        | `emerg`              | 系统崩溃级故障（如内核崩溃） |
| `-k`      | 仅显示内核日志    | `alert`              | 需立即修复（如数据库损坏）   |
| `-n N`    | 显示最近 N 条日志 | `crit`               | 高危故障（如硬盘错误）       |
| `-p 等级` | 按等级筛选        | `err`                | 一般故障（如服务启动失败）   |
| `-f`      | 实时追踪日志      | `warning`            | 警告（如参数配置不当）       |
| `--since` | 指定起始时间      | `info`               | 普通信息（如服务正常启动）   |
| `--until` | 指定结束时间      | `debug`              | 调试信息（开发排障用）       |

## 二、网站服务程序

### （一）Web 网络服务定义

- 被动访问服务程序，接收互联网主机请求后，通过 HTTP/HTTPS 协议将请求内容传送给用户。

### （二）Apache 程序特点

- 跨平台、安全性高，拥有快速、可靠、简单的 API 扩展，可运行于 Linux、UNIX、Windows 系统。
- 支持实时监视服务状态、定制日志消息，兼容丰富模块，市场占有率高。

### （三）Apache 安装与启用步骤

1. 挂载系统镜像到 /media/cdrom 目录。
2. 用 Vim 创建软件仓库配置文件。
3. 执行`dnf install httpd`命令安装 Apache 服务。
4. 启用并设置开机自启：`systemctl start httpd`、`systemctl enable httpd`。

### （四）默认页面访问

- 浏览器地址栏输入`http://127.0.0.1`，可查看 Apache 默认测试页面，网站数据默认存放目录为 /var/www/html。

## 三、配置服务文件参数

### （一）核心文件与目录

| 作用         | 文件 / 目录名称            |
| ------------ | -------------------------- |
| 服务目录     | /etc/httpd                 |
| 主配置文件   | /etc/httpd/conf/httpd.conf |
| 网站数据目录 | /var/www/html（默认）      |
| 访问日志     | /var/log/httpd/access_log  |
| 错误日志     | /var/log/httpd/error_log   |

### （二）主配置文件参数结构

- 注释行：以`#`开头，用于说明功能或参数含义。
- 全局配置：作用于整个 Apache 服务，如`ServerRoot "/etc/httpd"`。
- 区域配置：针对特定目录或功能的配置，如`<Directory />`、`<Location /server-status>`。

### （三）常用配置参数

| 参数           | 作用                        |
| -------------- | --------------------------- |
| ServerRoot     | 服务目录                    |
| ServerAdmin    | 管理员邮箱                  |
| User           | 运行服务的用户              |
| Group          | 运行服务的用户组            |
| ServerName     | 网站服务器的域名            |
| DocumentRoot   | 网站数据目录                |
| Listen         | 监听的 IP 地址与端口号      |
| DirectoryIndex | 默认的索引页页面            |

| CustomLog      | 访问日志文件                |
| Timeout        | 网页超时时间（默认 300 秒） |

### （四）修改网站数据目录实操

1. 编辑主配置文件：将`DocumentRoot`（约 122 行）及相关`Directory`参数（约 127 行、134 行）修改为目标目录（如 /home/wwwroot）。
2. 重启服务：`systemctl restart httpd`。
3. 注意：若出现 403 权限不足报错，需检查目录权限及 SELinux 配置。

## 四、SELinux 安全子系统

### （一）定义与作用

- SELinux（Security-Enhanced Linux）：强制访问控制（MAC）安全子系统，约束服务进程仅获取必要资源，从服务功能、文件访问两方面监控越权行为。

### （二）三种工作模式

| 模式       | 特点                             |
| ---------- | -------------------------------- |
| enforcing  | 强制启用安全策略，拦截不合法请求 |
| permissive | 越权访问时仅警告，不强制拦截     |
| disabled   | 不警告、不拦截越权行为           |

### （三）semanage 命令（SELinux 策略管理）

- 语法：`semanage [参数] [文件/端口]`

- 常用参数：

  | 参数 | 作用     |
  | ---- | -------- |
  | -l   | 查询策略 |
  | -a   | 添加策略 |
  | -m   | 修改策略 |
  | -d   | 删除策略 |

- 功能：管理文件 / 目录策略、网络端口、消息接口，功能优于传统 chcon 命令。

### （四）关键操作

- 修改安全上下文后，执行`restorecon`命令使其立即生效。
- 查询 HTTP 相关 SELinux 域策略：`getsebool -a | grep http`（off = 禁止，on = 允许）。

## 五、个人用户主页功能

### （一）启用步骤

1. 默认未开启，需先在用户家目录创建网站数据目录（如 /public_html）及首页文件（index.html）。
2. 重启 httpd 服务：`systemctl restart httpd`。
3. 访问格式：`网址/～用户名`（波浪号不可省略，无空格）。
4. 报错处理：若出现 403 禁止访问，需通过 getsebool 命令检查并开启 HTTP 相关安全策略。

### （二）添加密码认证功能

1. 生成密码数据库：`htpasswd -c /etc/httpd/passwd username`（-c 创建新文件，username 为用户名）。

2. 编辑个人主页配置文件（如 /etc/httpd/conf.d/userdir.conf），添加认证规则：

   ```plaintext
   <Directory "/home/*/public_html">
     AuthType Basic
     AuthName "My privately website"
     AuthUserFile /etc/httpd/passwd
     Require valid-user
   </Directory>
   ```

3. 重启服务后访问，需输入用户名和密码验证（401 Unauthorized 提示验证）。

## 六、虚拟主机功能

### （一）概念

- 将物理服务器虚拟为多个 “虚拟服务器”，共享硬件资源（无硬件隔离），通过 IP 地址、主机域名、端口号区分不同网站，成本低廉。

### （二）三种部署方式

#### 1. 基于 IP 地址

- 前提：服务器配置多个独立 IP（如 192.168.10.10、192.168.10.20、192.168.10.30），且 IP 与网站一一对应。

- 步骤：

  1. 用 nmtui 命令配置网络参数，ping 命令验证 IP 连通性。

# 使用 Samba 或 NFS 实现文件

## 一、Samba 文件共享服务

### （一）基础介绍

Samba 服务用于实现 Linux 与 Windows、Linux 与 Linux 系统间的文件共享，基于 SMB 协议，其配置方式与多数 Linux 服务类似，核心是通过配置文件定义共享规则、用户认证等信息。

### （二）安装与配置文件

1. **安装**：通过软件仓库安装 Samba 服务程序（软件包名即为`samba`）。
2. **主配置文件**：核心配置文件包含全局参数、共享模块等，关键参数及作用如下：

| 行数 | 参数                          | 作用                                 |

| 10   | passdb backend = tdbsam       | 用户后台类型                         |
| 16   | [homes]                       | 家目录共享模块标识                   |
| 18   | valid users = %S, %D%w%S      | 允许访问的账户                       |
| 19   | browseable = No               | 不在 “网上邻居” 显示共享信息         |
| 20   | read only = No                | 允许写入操作                         |
| 22   | [printers]                    | 打印机共享模块标识                   |

### （三）安全验证方式

Samba 服务支持 4 种安全验证方式，具体如下：

1. `share`：无需验证密码，匿名访问，安全性差。
2. `user`：需账号密码认证，默认且最常用。
3. `domain`：通过域控制器认证，限制用户来源域。
4. `server`：独立主机验证密码，集中管理账号，不常用。

## 二、NFS（网络文件系统）

### （一）基础介绍

NFS 仅支持 Linux 系统间的文件共享，通过网络将服务器的文件系统挂载到客户端，实现资源共享，依赖 RPC（远程过程调用）服务传递服务器 IP 和端口信息。

### （二）实验环境

| 主机名称   | 操作系统 | IP 地址       |
| ---------- | -------- | ------------- |
| NFS 服务器 | RHEL 10  | 192.168.10.10 |
| NFS 客户端 | RHEL 10  | 192.168.10.20 |

### （三）配置步骤

1. **安装服务**：默认未安装时，执行`yum install nfs-utils`安装。
2. **创建共享目录**：`mkdir /共享目录名`，设置权限确保客户端可写入（如`chmod 777 /共享目录名`）。
3. **修改配置文件**：编辑`/etc/exports`，格式为`共享目录路径 允许访问的客户端（权限参数）`，示例：`/home/nfs 192.168.10.0/24(rw,sync,all_squash)`。
4. **启动服务**：先启动 RPC 服务（`systemctl start rpcbind`），再启动 NFS 服务（`systemctl start nfs`），并设置开机自启。

### （四）关键参数

1. 配置文件参数

   ：

   

   | 参数 | 作用 |

   

   |------|------|

   

   | ro | 只读权限 |

   

   | rw | 读写权限 |

   

   | root_squash | 客户端 root 映射为服务器匿名用户 |

   

   | no_root_squash | 客户端 root 映射为服务器 root |

   

   | all_squash | 客户端所有账户映射为服务器匿名用户（推荐，提升安全性） |

   

   | sync | 数据同时写入内存和硬盘，不丢失数据 |

   

   | async | 数据先存内存再写硬盘，效率高但可能丢失数据 |

2. showmount 命令参数

   （用于查看 NFS 共享信息）：

   

   | 参数 | 作用 |

   

   |------|------|

   

   | -e | 显示 NFS 服务器的共享列表 |

   

   | -a | 显示本机挂载的 NFS 资源情况 |

   

   | -v | 显示版本号 |

### （五）客户端访问

客户端执行`mount -t nfs 服务器IP:共享目录 本地挂载目录`即可挂载，例如`mount -t nfs 192.168.10.10:/home/nfs /mnt/nfs`。

## 三、autofs 自动挂载服务

### （一）核心作用

autofs 是 Linux 系统守护进程，与`mount`命令手动挂载不同，它能动态挂载文件系统：仅当用户试图访问未挂载的文件系统时，才自动完成挂载，提升资源利用率。

### （二）配置规则

1. **主配置文件**：按 “挂载目录（上一级目录） 子配置文件” 格式填写。
2. **子配置文件**：按 “挂载目录 挂载类型及权限：设备名称 / 共享路径” 格式填写。

# 使用 BIND 提供域名解析服务笔记

## 一、DNS 域名解析服务基础

### （一）核心概念与作用

- **定义**：域名系统（DNS）是管理和解析域名与 IP 地址对应关系的技术，采用目录树层次结构构建分布式数据库，降低用户访问网络资源的门槛。
- **核心作用**：实现域名与 IP 地址的相互转换，支持网络资源的便捷访问。

### （二）域名结构与后缀

1. **层次结构**：根域（.）→顶级域（如.com、.edu）→二级域（如[linuxprobe.com](https://linuxprobe.com/)）→主机名（如 www、bbs）。

2. 常见后缀分类

   ：

   - 国际域名：.com（商业组织）、.gov（政府部门）、.edu（教育机构）、.net（网络服务商）、.org（非营利组织）、.pub（公共大众）等。
   - 国内域名：.cn（中国）等。

### （三）DNS 服务器类型

| 服务器类型 | 核心功能                                     |
| ---------- | -------------------------------------------- |
| 主服务器   | 特定区域内唯一，维护该区域域名与 IP 对应关系 |
| 从服务器   | 从主服务器同步对应关系，保障服务高可用       |
| 缓存服务器 | 缓存常用解析记录，提升重复查询效率           |

### （四）解析查询方式

1. **递归查询**：DNS 服务器必须向用户返回准确查询结果（用户与 DNS 服务器之间）。
2. **迭代查询**：DNS 服务器返回另一台 DNS 服务器地址，用户依次查询至获取结果（DNS 服务器之间）。

### （五）根 DNS 服务器

- 共 13 个逻辑 IP 地址，对应 504 台实际服务器，分布全球，用于负载均衡和抵抗 DDoS 攻击。

## 二、BIND 服务程序安装与配置

### （一）BIND 服务简介

- BIND（Berkeley Internet Name Domain）是全球最广泛使用的域名解析服务程序，安全可靠且高效。
- 推荐安装`chroot`扩展包（牢笼机制），限制 BIND 仅操作自身配置文件，保障服务器安全。

### （二）关键配置文件

| 文件 / 目录      | 路径                     | 核心作用                                     |
| ---------------- | ------------------------ | -------------------------------------------- |
| 主配置文件       | /etc/named.conf          | 定义 BIND 服务运行参数（约 30 行有效配置）   |
| 区域配置文件     | /etc/named.rfc1912.zones | 记录域名与 IP 对应关系的文件位置（类似目录） |
| 数据配置文件目录 | /var/named               | 存放域名与 IP 真实对应关系的数据文件         |

### （三）核心解析参数

1. **正向解析**（域名→IP）：

```plaintext
zone "linuxprobe.com" IN{
    type master;  # 服务类型为主服务器
    file "linuxprobe.com.zone";  # 数据文件路径
    allow-update { none; };  # 禁止动态更新
};
```

1. **反向解析**（IP→域名）：

```plaintext
zone "10.168.192.in-addr.arpa" IN{  # 对应192.168.10.0/24网段
    type master;
    file "192.168.10.arpa";
    allow-update { none; };
};
```

### （四）域名解析记录类型

| 记录类型 | 作用                                  |
| -------- | ------------------------------------- |
| A        | 域名指向 IPv4 地址                    |
| CNAME    | 域名指向另一域名                      |
| AAAA     | 域名指向 IPv6 地址                    |
| NS       | 子域名指定其他 DNS 服务器解析         |
| MX       | 域名指向邮件服务器地址                |
| SRV      | 记录特定服务的服务器                  |
| TXT      | 存储文本信息（如 SPF 反垃圾邮件记录） |
| CAA      | CA 证书颁发机构授权校验               |
| 显性 URL | 域名重定向（显示目标地址）            |
| 隐性 URL | 域名重定向（隐藏目标地址）            |

### （五）部署缓存服务器

### （六）分离解析技术

| 主机       | 操作系统   | IP 地址                                  |
| ---------- | ---------- | ---------------------------------------- |
| DNS 服务器 | RHEL 10    | 北京：122.71.115.10；美国：106.185.25.10 |
| 北京用户   | Windows 10 | 122.71.115.1                             |
| 海外用户   | Windows 10 | 106.185.25.1                             |

1. 主配置文件：监听端口和允许查询设为`any`，删除根域配置。
2. 区域配置文件：按不同网段创建区域（如北京、美国）。
3. 数据配置文件：分别指向对应区域的服务器 IP（北京→122.71.115.15；美国→106.185.25.15）。
4. 验证：不同地区用户访问同一域名，解析到就近服务器。
